# 마크다운 문서 — 문법 입구 안내서

Itda Doc 으로 보고서·제안서·기안문·회의록·발표 자료를 쓰는 사람(과 그 문서를 대신 쓰는 Claude)을 위한 **입구**다.
문법은 이 안내서와 주제별 안내서가 정본이다 — 차트 [charts.md](charts.md), 수식 [math.md](math.md),
그림 [diagrams.md](diagrams.md), 발표 [slides.md](slides.md).
Itda Hyve Docs 문서 창 쓰는 법(보기 꼴·편집기·단축키·PDF·명령줄)은 [GUIDE-document-window.md](https://github.com/itda-work/itda-hyve/blob/main/docs/GUIDE-document-window.md), 회사 테마 만들기는 [themes.md](themes.md),
왜 이렇게 정했는지는 설계 [DESIGN-markdown-docs.md](https://github.com/itda-work/itda-hyve/blob/main/docs/DESIGN-markdown-docs.md) 1장이다.

## 1. 빠른 시작

문서는 **보통의 마크다운**(CommonMark + GitHub 표·작업 목록·취소선·각주·알림)이다. 거기에 Pandoc 계열의 사실상 표준 몇 가지(frontmatter·정의 목록·속성 `{#id .class}`·표 캡션·`:::` 컨테이너)를 더했다.
새 기호를 만들지 않았으므로 GitHub·VS Code·Obsidian 에서 열어도 내용이 깨지지 않는다.

- **모양은 테마가 정한다.** 문서에는 뜻만 적는다 — 색·글꼴·여백을 적는 문법은 없다. `theme:` 으로 테마를 고른다.
- **쪽 나눔은 저절로 된다.** 문서 창이 A4 쪽으로 나눈다. 꼭 나눠야 할 곳에만 `<!-- pagebreak -->` 를 쓴다.
- **표가 차트가 된다.** GFM 표를 `:::chart` 로 감싼다. 수식은 `$…$`·`$$…$$`, 흐름도는 ```` ```mermaid ````.
- **raw HTML 은 그리지 않는다**(몇 가지 태그 말고). 경고로 알린다.
- **경고는 줄 번호와 함께 나온다.** 경고 0 이 목표다 — 코드마다 고치는 법은 9장.

완성된 최소 문서:

```markdown
---
title: 2026년 4분기 사업 계획
author: 홍길동
date: 2026-10-14
theme: classic
toc: true
number-sections: true
---

:::lead
4분기에는 신규 고객 30곳을 목표로 한다.
:::

# 현황

3분기 매출은 **44.9억 원**으로 전 분기보다 8% 늘었다.

:::chart{type=bar unit="억 원"}
| 분기 | 2025 | 2026 |
|---|--:|--:|
| 1분기 | 31.0 | 38.2 |
| 2분기 | 35.4 | 41.5 |
| 3분기 | 39.1 | 44.9 |

: 분기별 매출
:::

# 계획

1. 신규 고객 30곳
2. 재계약률 90% 유지

> [!NOTE]
> 세부 일정은 붙임을 본다.
```

**주제별 문법**(Claude 는 `md_syntax(주제)` 또는 `itda-hyve md --syntax 주제` 로 같은 글을 받는다):

| 주제 | 내용 | 안내서 |
|---|---|---|
| `core` | frontmatter, 제목·번호, 쪽 나눔, 컨테이너, 알림, 그림·표 캡션, 목차, 각주·정의 목록, 링크·이미지·HTML, 목록 기호 사다리, 경고 코드, 지원하지 않는 것 | 이 안내서 2~10장 |
| `charts` | `:::chart` — 종류 9가지, 속성, 숫자 읽기, 상한, 경고 | [charts.md](charts.md) |
| `math` | `$…$`·`$$…$$`·```` ```math ```` — 달러 기호 규칙, 지원 범위, 상한 | [math.md](math.md) |
| `diagrams` | ```` ```mermaid ```` 흐름도 — 지원 문법, 그리지 않는 것, 상한 | [diagrams.md](diagrams.md) |
| `slides` | 슬라이드 나눔, `slides:`, 차례로 나타내기, 발표자 노트 | [slides.md](slides.md) |

문서 작업 순서(사람이든 Claude 든): 필요한 주제의 문법을 읽는다 → 쓴다 → 문서 창의 경고 단추(또는 `md_check`·`itda-hyve md --check`)로 경고를 본다 → 고친다.
경고를 숨기려고 데이터를 지우지 않는다(차트 상한을 넘으면 차트를 나누거나 `table=below` 로 표를 함께 싣는다).

## 2. frontmatter — 문서 정보

파일 맨 앞의 `---` 와 `---`(또는 `...`) 사이 YAML 블록이다. 키 이름은 Pandoc 을 따른다(kebab-case). 모두 선택이다.
값은 글자로만 쓰인다(HTML 로 해석하지 않는다). 닫는 줄이 없으면 frontmatter 가 아니다(첫 줄의 가로줄로 읽힌다).

<!-- fm-keys:begin -->
| 키 | 값 | 기본 | 뜻 |
|---|---|---|---|
| `title` | 글자 | 없음 | 문서 제목(표지·머리글) |
| `subtitle` | 글자 | 없음 | 부제 |
| `author` | 글자 또는 글자 목록(`- name: …` 꼴도) | 없음 | 쓴 사람 |
| `date` | 글자 | 없음 | 날짜. 적은 글자 그대로 보인다 |
| `lang` | 글자 | 없음(한국어) | 비어 있거나 `ko` 로 시작하면(`ko-KR`) 알림 제목이 한국어, 그 밖은 영어 |
| `toc` | `true`·`false` | `false` | 목차를 넣는다(7장) |
| `toc-depth` | 1~6 | 3 | 목차에 넣는 제목 단계 |
| `number-sections` | `true`·`false` | `false` | 제목 번호 1. / 1.1 / 1.1.1 |
| `papersize` | `a4`·`a4-landscape` | `a4` | 종이 |
| `theme` | 테마 이름 또는 별칭 | `classic` | 테마(3장) |
| `cover` | `true`·`false` | 테마가 정함 | 표지 쪽 |
| `doc-no` | 글자 | 없음 | 문서 번호(표지·머리글) |
| `version` | 글자(`"1.2"` 처럼 따옴표) | 없음 | 판 |
| `classification` | 글자 | 없음 | 보안 등급(표지·머리글. 예: 대외비) |
| `organization` | 글자 | 테마가 정함 | 조직 이름 |
| `list-style` | `gaejosik`·`gongmun`·`plain` 또는 `[gaejosik, gongmun]` | 테마가 정함 | 목록 기호 사다리(8장) |
| `code` | `true`·`false` 또는 설정 매핑 | 줄 번호 켬 | 코드 블록 표시 — `line-numbers: false` 로 줄 번호를 끈다(8장) |
| `slides` | `true` 또는 설정 매핑 | 없음 | 발표 자료 — 키는 [발표 안내서](slides.md) |
<!-- fm-keys:end -->

- 표에 없는 키도 버리지 않고 순서대로 테마에 넘긴다. `mono` 테마의 `수신`·`참조`·`시행일` 처럼 테마가 표지·머리글에 쓰는 값이다.
- 아는 키의 값 꼴이 틀리면 그 키만 무시하고 `frontmatter-value` 경고를 낸다. YAML 이 깨졌으면 블록 전체를 본문으로 그리고 `frontmatter-invalid` 경고를 낸다.
- `version: 1.10` 처럼 숫자로 읽히는 값도 이 앱은 적은 글자 그대로 쓴다. 다른 YAML 도구에서 숫자(`1.1`)로 바뀌지 않게 따옴표를 권한다.

### 폴더 기본값 `_metadata.yml`

폴더마다 두는 `_metadata.yml` 이 그 폴더의 문서 frontmatter 기본값이 된다(#474). 문서마다 같은 설정을 반복해 적지 않아도 된다 — `slides.font-scale`, 테마, 조직 이름, 목록 기호 사다리 같은 공통 값을 폴더에 둔다.

```yaml
# _metadata.yml — 예: 발표 자료 폴더의 공통 설정
slides:
  font-scale: 0.8
theme: bold
organization: 잇다
```

- 문서 frontmatter 가 폴더 값보다 앞선다: **문서 > 같은 폴더 > 위 폴더 > 테마 기본**. 파일끼리 키 단위로 합치는 것은 `slides:`·`code:` 뿐이고(폴더에 `slides.ratio`, 문서에 `slides.font-scale` 이 있으면 둘 다 적용), 그 밖의 값 — 모르는 키의 맵 포함 — 은 문서에 있으면 통째로 문서 값을 쓴다. 옛 별칭 표기(`font_scale`)는 문서·폴더 파일 사이에서 같은 키로 견준다(경고는 적은 표기 그대로 `slides.font_scale` 로 난다). 폴더 파일이 적용되면 각 파일 안에서 같은 키가 겹칠 때 **마지막 값이 이긴다**(별칭 표기끼리도) — 앞 값이 옳고 뒤 값이 틀려도 틀린 값이 이기고 그 키는 경고와 함께 무시되니, 겹친 키는 정리하고 쓰라. 문서 frontmatter 의 경고는 폴더 파일이 있어도 없을 때와 같다(겹친 키의 앞 값 경고도 그 줄로 남는다). 폴더 파일이 하나도 적용되지 않으면 문서는 폴더 기능이 없을 때와 같이 처리된다(중복 키 해석도 그대로).
- **문서가 슬라이드로 열리는지는 문서 자신의 `slides:` 값으로 정한다.** 폴더에 `slides:` 가 있어도 문서에 `slides:` 가 없으면 슬라이드로 열리지 않는다. 이때 `folder-slides-unused` 경고로 어느 폴더 파일의 `slides:` 를 쓰지 않았는지 알린다(#543 — 문서가 `slides: false` 로 정했으면 내지 않는다). `slides: false` 는 「슬라이드 아님」을 정한 것이다(폴더의 `slides` 값도 쓰지 않는다). 문서가 `slides: true`(또는 빈 값)로 슬라이드임만 정했다면 하위 설정은 폴더 값으로 채워진다.
- 문서 폴더부터 위로 찾는다. 문서가 홈 아래면 **홈 폴더의 파일까지 읽고 그 위로는 가지 않는다**. 홈 밖(외장 디스크 등)의 문서는 볼륨 루트까지 — macOS 는 `/Volumes/<디스크>` 폴더의 파일까지 읽고 멈추고, Windows 는 드라이브 루트(`C:\`)까지다. 파일 하나는 64KB 까지이고, 심볼릭 링크는 따라간다.
- 폴더 파일의 값 꼴이 틀리면 **그 키만 무시하고 나머지는 적용**한다. YAML 이 깨졌거나 키: 값 모양이 아니거나 읽지 못하면 **그 파일만 건너뛰고** 경고로 알린다 — 파일 건너뛰기 경고에는 그 파일의 상대 경로가 있고, 값 경고에는 상대 경로와 그 파일의 줄이 있다(`../_metadata.yml 3줄:` 처럼, 문서 줄 번호와는 다르게 줄이 0 으로 나온다). 문서 렌더는 멈추지 않는다. YAML 앵커·병합 키(`&a`·`*a`·`<<:`)는 문서 frontmatter 와 같이 풀지 않는다.
- 문서 창의 문서 이름 옆에 「폴더 설정 적용됨: `../_metadata.yml`」 표시로 어느 파일이 얹혔는지 볼 수 있고(마우스를 올리면 전체 목록 — 테마를 폴더에서 받았으면 테마 고르기에도 「(폴더 설정: `../_metadata.yml`)」 로 보인다), 폴더 파일을 고치면 열린 문서가 다시 그려진다 — 감시는 수정 시각·크기로 알아챈다. 공유 화면·PDF 내보내기·`md_check`(path)도 같은 값을 쓴다.
- 문서를 다른 곳으로 보내면 폴더 값은 따라가지 않는다(문서에 적은 값만 있다). 공통 값을 문서마다 꼭 남겨야 할 때는 문서 frontmatter 에 직접 적는다.

#### 폴더 설정 편집 화면

이 파일은 문서 창에서 만들고 고칠 수 있다(문서 머리줄의 문서 메뉴 「폴더 설정…」, 또는 「폴더 설정 적용됨」 표시를 누르기 — 저장해서 경로가 있는 문서에서만 켠다).

- **대상 폴더**를 문서 폴더부터 위로 고른다(홈 폴더까지 — ① 의 찾기 범위와 같다). 파일이 이미 있는 폴더는 표시로 알린다.
- 한 줄 = 체크 + 값 칸. **체크하면 이 폴더에서 정하는 것**이고, 해제하면 그 키를 파일에서 뺀다(위 폴더·테마·기본값을 물려받는다 — 해제한 줄에 실제 적용되는 값과 출처를 흐리게 보인다). 체크했을 때 칸의 첫 값은 물려받는 값이다.
- 제목·부제·날짜·문서 번호·판은 「문서마다 다른 값」으로 접혀 있다(막혀 있지는 않다 — 폴더에 두면 그 폴더 문서의 기본값이 된다). 문서가 이미 그 키를 정하고 있으면 줄에 「문서에서 정함」으로 알린다(문서가 폴더보다 이긴다).
- 값은 저장 전에 검사한다 — 범위 밖 숫자(`font-scale: 2`), 모르는 테마 이름 같은 값은 그 줄에서 막힌다.
- 오른쪽의 **저장될 YAML** 미리 보기와 **지금 문서에 적용해 보기**(미리보기 화면이 그 값으로 잠시 바뀐다 — 되돌리기로 돌아온다)로 저장할 내용을 먼저 본다. 그리는 동안(닫거나 폴더를 바꿀 때 되돌리는 동안 포함)에는 이 단추와 저장 단추가 잠깐 잠긴다(「그리는 중…」).
- 이미 있는 파일을 고칠 때 **화면에 없는 키(`author`, `slides:` 맵 자체, 모르는 키)는 그대로** 둔다(개수를 알린다). **주석은 최상위 키의 주석만 지킨다** — `slides:`·`code:` 블록을 고치면 그 안을 통째 다시 쓰기 때문에 블록 안 주석은 사라질 수 있고, 사라지면 저장 전에 「주석 n줄이 사라집니다」로 알린다. 옛 별칭 표기(`fontscale`)로 적힌 키는 저장하면 정본 이름으로, 옛 값 표기도 정규 값으로 적는다(`16/9` → `16:9`, 테마 별칭 → 테마 이름). 파일 안에서 같은 키가 겹치면 마지막 값으로 읽고, 저장하면 하나로 남는다(폼이 미리 알린다 — `slides:`·`code:` 블록이 겹친 것도 같다). `slides: true` 처럼 맵이 아닌 그룹 값은 화면에서 고칠 수 없다(그대로 둔다). YAML 앵커·별칭·병합 키(`&a`·`*a`·`<<`)가 있는 파일도 화면에서 고칠 수 없다 — 값을 다시 쓰면 파일이 깨질 수 있어서다.
- 폼이 보여 주는 「적용될 값·출처」와 저장 전 검사는 문서를 렌더할 때와 같은 계산을 쓴다 — 범위를 벗어난 위 폴더 값은 원문과 함께 「무시됨」으로, 문서가 그 키를 정했으면 「문서에서 정함」으로 보인다. 저장 전 검사는 그 폴더의 파일 자체를 본다(체크한 값이 그대로 들어가고 ① 파서가 받는지) — 지금 문서에서 더 가까운 폴더·문서가 이기는 값은 오류가 아니라 안내만 보인다. 폼을 연 뒤 그 탭의 문서가 바뀌면(다른 이름으로 저장) 저장을 거부하고 폼을 다시 열게 한다.
- 위 폴더의 파일을 읽지 못하면(64KB 넘음·권한·깨진 YAML) 폼 아래 안내에 문서 경고와 같은 문구(`../../_metadata.yml: 파일이 너무 큼(64KB 넘음) — 건너뜀`)로 알리고, 그 파일의 값은 물려받는 값에 넣지 않는다.
- 폼을 연 뒤 밖에서 파일이 바뀌면 저장이 막히고 다시 읽기·덮어쓰기를 묻는다 — 저장을 누를 때와, 새 내용을 다 쓴 뒤 제자리에 놓기 직전에 한 번 더 본다. 그 뒤 놓기까지의 아주 짧은 틈에 밖에서 쓴 것은 막지 못한다(미검증·남는 창). 쓰기는 그 폴더의 `_metadata.yml` 한 이름으로만 하고, 임시 파일을 나만 읽고 쓰는 권한으로 만들어 다 쓴 뒤 기존 파일의 권한(예: 0600)으로 맞춰 바꿔 넣는다 — 저장하는 동안 다른 사용자에게 기존보다 넓게 열리지 않는다. 읽는 사이 파일이 사라졌거나 놓기 직전에 권한이 바뀌었으면 저장하지 않고 다시 읽기·덮어쓰기를 묻는다. 파일을 읽지 못하면(읽기 권한 없음 등) 오류를 보이고 저장하지 않는다. 파일이 없던 폴더에는 새로 만들되, 그 사이 같은 이름의 파일이 생겼으면 덮지 않는다(링크를 못 쓰는 파일 시스템에서는 틈이 남는다 — 미검증). 값을 모두 빼고 저장해도 파일을 지우지 않는다(최상위 주석·모르는 키가 남는다; 파일이 없으면 만들지도 않는다).
- 저장하면 열린 문서가 저절로 다시 그려진다(폴더 파일 감시 — 따로 새로 고침할 필요가 없다).

## 3. 테마

`theme:` 에 이름이나 별칭을 적는다. 없으면 `classic` 다. 모르는 이름이면 `classic` 으로 보이고 `unknown-theme` 경고가 난다. 옛 이름(`report`·`proposal`·`official`·`minutes`·`manual`)과 옛 별칭도 내장 테마에서는 모르는 이름이다(#549) — 같은 이름의 사용자 테마가 있으면 그 테마로 열린다. 회사 테마의 `"extends": "report"` 도 새 이름(`classic`)으로 고쳐야 한다.

<!-- themes:begin -->
| 이름 | 별칭 | 쓰임 |
|---|---|---|
| `classic` | 클래식 | 남색 한 가지 강조색. 띠 두른 표지, 제목 번호, 머리글에 조직·문서 제목 |
| `bold` | 볼드 | 강조색 면 표지, 큰 장 번호, 장 앞 쪽 나눔(쪽이 35% 넘게 찼을 때), 돋보이는 요약문·상자 |
| `mono` | 모노 | 흑백. 표지 없이 가운데 제목 블록, 수신·참조 줄, 결재란, 발신 명의. 목록 기호 사다리(개조식·공문)가 켜져 있다 |
| `compact` | 컴팩트 | 표지 없이 촘촘한 한 장. 맨 위 정보 표, 결정 사항 상자·할 일 표(`:::decisions`·`:::actions`) |
| `spine` | 책등 | 책등 표지, 「제 n 장」 장 머리, 장마다 새 쪽, 번호 원 단계 상자(`:::steps`·`:::result`) |
<!-- themes:end -->

회사 테마는 `~/.itda/hyve/themes/<이름>/` 에 두고 같은 방식으로 이름을 적는다([테마 안내서](themes.md)).

## 4. 제목 — id·속성·번호

- **id** 는 GitHub 과 같은 규칙으로 저절로 붙는다(소문자, 공백 → `-`, 한글은 그대로, 겹치면 `-1`·`-2`). `[현황으로](#현황)` 이 GitHub 에서처럼 동작한다.
- **속성**: `## 제목 {#custom-id .class}`. 속성을 하나라도 읽지 못하면 `{…}` 전체를 글자로 남기고 `bad-attribute` 경고를 낸다. 직접 적은 id 가 겹치면 `duplicate-id` 경고.
- **번호**: `number-sections: true` 면 렌더러가 번호를 넣는다. `{-}` 또는 `{.unnumbered}` 는 번호를 건너뛰고, `{.unlisted}` 는 목차에서만 뺀다(번호는 받는다).
- **기준 단계**: 번호와 `toc-depth` 는 문서에서 **가장 높은 제목 단계를 1로** 센다. frontmatter `title` 을 두고 `##` 부터 써도 번호는 `1` 부터다.

```markdown
# 개요

## 배경 {#bg}

## 참고 자료 {-}

## 내부 메모 {.unlisted}
```

## 5. 쪽 나눔

쪽은 문서 창이 저절로 나눈다(표 머리는 다음 쪽에 되풀이, 그림·알림·`box`·결재란은 통째로 옮긴다). 꼭 나눠야 할 곳에만 쓴다.

| 표기 | 구분 |
|---|---|
| `<!-- pagebreak -->` | **쓰는 표기** — 다른 뷰어에서 안 보인다 |
| `<div style="page-break-after: always"></div>` | 받아들임(Typora·Obsidian 관용) — 다른 뷰어에서는 인쇄 때 같은 동작 |
| `\newpage` (한 줄 단독) | 받아들임(Pandoc 관용) — 다른 뷰어에서 글자로 보인다 |

- 블록 자리(앞뒤 빈 줄)에서만 쪽 나눔이다. 문단 안의 주석·`\newpage` 는 아니다.
- `#` 앞에서 늘 쪽을 나누는 것은 문법이 아니라 테마 설정이다.
- 쪽 사이에서 쪼개지 않으려는 블록은 `:::keep` 으로 감싼다.

```markdown
첫 쪽의 끝.

<!-- pagebreak -->

# 둘째 쪽
```

## 6. 컨테이너 `:::`

표준에 없는 블록(가운데 정렬·다단·서명란·요약문)은 Pandoc 의 fenced div 하나로 쓴다.

- **여는 줄**: 콜론 3개 이상 + 이름(`:::이름` 또는 `::: 이름`) 그리고/또는 속성 `{…}`. 이름은 글자·숫자·`-`·`_`(한글 가능). 앞에 빈 줄이 있어야 열린다(문단 중간에서는 안 열린다).
- **닫는 줄**: 콜론만 있는 줄. 가장 안쪽 컨테이너를 닫는다. 바깥 것에는 콜론을 더 많이 쓴다(`::::columns`). 닫지 않으면 문서 끝에서 닫히고 `unclosed-container` 경고가 난다.
- **닫는 줄의 들여쓰기**: 닫는 줄은 줄 맨 앞(들여쓰기 0~3칸)에 둔다. 4칸 이상 들여쓴 `:::` 는 닫는 줄이 아니라 목록의 이어지는 글·코드로 읽힌다. 목록 바로 뒤에서 닫을 때는 빈 줄을 하나 둔다 — 빈 줄이 없으면 포매터(Prettier 등)가 그 줄을 목록 글로 보고 들여쓴다. 닫히지 않은 컨테이너 안에 이런 줄이 있으면 `indented-close` 경고가 난다(일부러 들여쓴 코드·목록 글도 후보가 되므로 「이 줄로 닫으려던 것이라면」 고치라고 안내한다). 문서 창 경고 목록의 「고치기」는 누를 때만 그 줄을 여는 `:::` 와 같은 칸(목록·각주 안이면 그 들여쓰기)으로 줄이고 앞에 빈 줄을 넣는다. 여는 줄이 `- :::box` 처럼 줄 머리 공백 뒤 바로 `:::` 로 시작하지 않으면 「고치기」 없이 경고만 난다.
- **속성**: `#id`·`.class`·`key=value`(값에 공백이 있으면 따옴표). `key=value` 는 `data-key` 로만 나간다. 예외는 `column` 의 `width` 하나(길이 꼴: 숫자 + `% mm cm in pt pc px em rem ch`, 단위 없으면 px).

<!-- containers:begin -->
| 이름 | 뜻 |
|---|---|
| `center` | 가운데 정렬 |
| `right` | 오른쪽 정렬(날짜·발신 명의) |
| `columns` | 다단 — 안에 `column` 들 |
| `column` | 단 하나. `{width=40%}` 로 너비 |
| `box` | 테두리 상자 |
| `lead` | 요약문(문서 첫머리) |
| `keep` | 쪽 사이에서 쪼개지 않음 |
| `signature` | 서명란 |
| `approval` | 결재란 — 안에 표를 쓴다 |
| `chart` | 차트 — [차트 안내서](charts.md) |
| `incremental` | 발표에서 목록을 하나씩 — [발표 안내서](slides.md) |
| `nonincremental` | 발표에서 하나씩 나타내기를 끔 — [발표 안내서](slides.md) |
| `notes` | 발표자 노트(문서·슬라이드에 안 보임) — [발표 안내서](slides.md) |
<!-- containers:end -->

모르는 이름도 `<div class="이름">` 으로 나간다 — 회사 테마가 자기 어휘로 쓴다. 내장 테마의 자기 어휘: `compact` 의 `decisions`(결정 사항)·`actions`(할 일 표), `spine` 의 `steps`(절차 단계)·`result`(단계의 결과).
강조 상자는 `note`·`warning` 컨테이너가 아니라 알림(`> [!NOTE]`)으로 쓴다.

```markdown
:::right
2026년 10월 14일
잇다워크 대표 홍길동
:::

::::columns
:::column{width=40%}
왼쪽 단
:::
:::column
오른쪽 단
:::
::::

:::approval
| 담당 | 팀장 | 본부장 |
|:-:|:-:|:-:|
| 홍길동 | | |
:::
```

## 7. 알림·그림·표 캡션·목차·각주·정의 목록

**알림**(GFM): `> [!NOTE]`·`[!TIP]`·`[!IMPORTANT]`·`[!WARNING]`·`[!CAUTION]` 다섯 가지. 표시가 첫 줄에 혼자 있어야 한다(대소문자 무시). 제목 글자는 `lang` 을 따른다.

<!-- alerts:begin -->
| 표시 | 제목(한국어) | 제목(그 밖) | 쓰임 |
|---|---|---|---|
| `NOTE` | 참고 | Note | 덧붙여 알아 둘 내용 |
| `TIP` | 팁 | Tip | 더 잘 쓰는 방법 |
| `IMPORTANT` | 중요 | Important | 꼭 알아야 할 내용 |
| `WARNING` | 주의 | Warning | 바로 주의해야 할 내용 |
| `CAUTION` | 경고 | Caution | 하면 위험하거나 되돌리기 어려운 일 |
<!-- alerts:end -->

```markdown
> [!WARNING]
> 결재 전에는 외부로 보내지 않는다.
```

**그림**: 이미지 하나만 있는 문단은 그림(`figure`)이 된다. 캡션은 **title**(따옴표 부분)이다 — 대체 글(alt)은 캡션이 아니다. 크기는 `{width=50%}` 로 정한다(6장의 길이 꼴). 슬라이드에서의 자리는 `{.fit}`·`{.left}`·`{.right}`·`{.full}`·`{.fill}`·`split=1:2` 로 고른다(`.left`·`.right` 패널과 `.full` 배경은 그림 하나뿐인 줄만, `.fit` 그림 2장 이상만 든 문단은 가로 배치) — 문서(A4)에서는 보통 그림이다([슬라이드 안내서](slides.md) 6장 「그림 배치」). 그 밖의 이미지 속성(id·다른 클래스·키)은 경고하고 버린다.

```markdown
![조직도](images/org.png "그림 캡션: 2026년 조직도"){width=70%}
```

**그림 캡션 문단**: 그림 **바로 다음** 문단을 `Figure:` 로 시작하면 그림 캡션이 된다(표 `Table:` 와 같은 꼴). 굵게·링크 같은 인라인 서식이 살고, title 캡션보다 우선한다. 문장 아래 줄에 붙인 이미지도 캡션이 있으면 그림으로 뗀다 — 마지막 줄이 이미지 하나뿐일 때만 떼고, 글과 섞인 줄은 그대로다. 그림 앞의 `Figure:` 문단은 글자고, `:` 짧은 접두는 정의 목록이 먼저 가져간다.

```markdown
설명 문장입니다.
![조직도](images/org.png)

Figure: 2026년 **조직도**
```

**표 캡션**: 표 **바로 다음** 문단을 `Table:` 또는 `:` 로 시작한다. 표 앞의 캡션은 받지 않는다(정의 목록과 겹친다).

```markdown
| 항목 | 금액 |
|---|--:|
| 인건비 | 1,200 |

Table: 예산(단위: 만 원)
```

**목차**: `toc: true` 면 표지(또는 제목) 다음에 넣는다. 자리를 정하려면 `[TOC]` 한 줄 문단을 쓴다(`toc` 값과 무관하게 그 자리에 그린다).

**각주**: `[^1]` 과 `[^1]: 내용`. 문서 끝에 모인다(쪽 아래 각주는 없다).

**정의 목록**: 용어 다음 줄 `: 설명`. 공문의 수신·제목 줄에 쓴다. 설명이 `1.` 로 시작하면 번호 목록이 되므로 `1\.` 로 쓴다.

```markdown
수신
: 각 부서장

붙임
: 1\. 세부 계획 1부. 끝.

본문에 각주를 단다.[^근거]

[^근거]: 2026년 3분기 결산 자료.
```

### 자료 표

미리보기 빌드의 문서 창(편집 모드)에서는 삽입 탭의 **자료 표** 로 작업공간에 보존된 결과를 표나 차트로 넣는다. 고를 수 있는 것은 채팅에서 `data.query` 로 받아 **공개 승인된** 결과뿐이다. 받은 적 없는 질의는 「발행되지 않음」으로 보이고 고를 수 없다 — 문서 창은 결과를 새로 만들지 않는다.

1. 커서를 넣을 자리에 둔다. **최상위 문단·제목·표 위나 빈 줄**이어야 한다. 목록·인용(알림)·각주 정의(`[^이름]:` 와 그 들여 쓴 내용)·`:::` 컨테이너(다단·차트) 안이면 넣지 않고 「최상위 문단에 커서를 두라」고 알린다.
2. 자료 → 질의 → 결과(판 이름·행 수·발행 시각)를 고르고, 넣는 꼴(표·차트)과 캡션을 정한다. 캡션을 비우면 「<자료 제목> · <판 이름> 기준」이다.
3. 넣기. 커서가 문단 가운데여도 문단을 가르지 않고 **그 문단 끝 다음**에 빈 줄을 두고 넣는다. 되돌리기 한 번으로 통째로 빠진다.

들어가는 글은 세 층이다 — 출처 기록 한 줄(HTML 주석), 표 또는 `:::chart`, 캡션.

```markdown
<!-- itda-data {"v":1,"ws":"5e1f7e57","dataset":"sales",…} -->
| 지점 | 매출(백만원) |
| :--- | -----------: |
| 강남 |          120 |

Table: 지점 매출 · 10월분 기준
```

- 머리글은 질의의 열 표시 이름(없으면 열 이름)이고 단위는 괄호로 붙는다. 값은 저장된 그대로다(천 단위 구분 없음).
- 출처 기록은 미리보기·PDF 에 보이지 않는다. 다만 문서 파일에는 남는다 — 문서를 보내면 작업공간 ID 앞 8자도 함께 간다(값·경로는 아니다).
- 기록 줄과 표 사이에 글을 끼우거나 기록 줄만 지우면 출처 연결이 끊긴다. 표 칸은 자유롭게 고쳐도 된다.
- 차트로 그릴 수 없는 결과(원 차트의 음수, 행·계열 상한 초과 등)는 넣지 않고 표로 넣으라고 알린다. 문서 표 상한은 CSV 표와 같다(데이터 행 1000·열 30·칸 1000자).
- CSV 표(문서 창 안내서 3장)는 커서 자리 그대로 넣는다 — 자료 표만 위 자리 규칙을 따른다.

**스냅샷 바꾸기.** 넣은 표·차트를 같은 자료·같은 질의의 다른 보존 결과(정정 판 등)로 바꾼다. 편집 모드에서 커서를 자료 표에 두고 삽입 탭의 **스냅샷 바꾸기**, 또는 미리보기의 자료 표·차트를 오른쪽 클릭해 **스냅샷 바꾸기…** 를 고른다.

1. 바꿀 결과(판 이름·질의 판·행 수·발행 시각)를 고른다. 지금 문서의 판에는 「지금 문서의 판」이 붙는다.
2. 바뀌는 칸·더하는 행·빼는 행을 미리 본다(첫 열 항목이 겹치지 않으면 항목끼리, 아니면 행 순서로 맞춘다).
3. 바꾸기. 출처 기록·표·캡션이 한 번에 바뀌고, 되돌리기 한 번으로 돌아온다.

- 캡션은 사람이 고친 글을 지킨다 — 캡션 안의 옛 판 이름이 한 곳에서 알아볼 수 있으면 그 부분만 새 판 이름으로 바꾸고, 아니면 그대로 둔다. 차트의 `type`·`unit` 같은 속성도 그대로다.
- 넣은 뒤 표 칸을 고쳤으면 「고친 것이 사라진다」는 확인을 골라야 바뀐다.
- 최상위 자료 표·차트만 바꾼다. 목록·인용·다단·각주 안이거나, 차트 안에 표·캡션 말고 다른 글이 있으면 바꾸지 않는다.
- 편집 모드 위 막대에 자료 표 상태 단추가 보이면 고친 블록(**수정됨**)이나 기록이 깨진 블록(**연결 끊김**)이 있다는 뜻이다 — 누르면 목록, 고르면 그 줄로 간다. 이 표시는 문서 글만 보고 정한다(작업공간을 열지 않는다). 출처가 작업공간에 있는지는 스냅샷 바꾸기를 열 때 본다. 미리보기·PDF 에는 나오지 않는다.

**채팅에서 받기.** AI 호스트는 `data.publish`(자료·질의, 꼴 `kind` table·chart 와 `chart_type`, 판 순번 `revision` 선택)로 같은 세 층 글을 받는다. 같은 보존 결과면 문서 창 **자료 표** 가 넣는 글과 바이트까지 같다(`internal/data/datadomain/publish.go`). 그 글을 고치지 않고 문서에 쓰면 문서 창에서 연결됨이다. 보존된 결과가 없으면 먼저 `data.query` 로 받으라고 돌려준다 — 새로 발행하지 않는다. 받는 칸 값은 `data.query` 와 같은 공개 승인 범위이고, 기록 주석의 작업공간 ID 앞 8자·지문 앞 16자와 캡션의 자료 제목·판 이름이 함께 호스트로 간다.

**기록 주석 문법**(쓰기 `FormatRecord`·읽기 `ParseRecord` — `internal/datareport/record.go`). 블록 바로 앞 한 줄이다. 접두 `<!-- itda-data `(공백 하나 포함), 접미 ` -->`, 사이는 JSON 객체 하나이고 키는 아래 열한 개가 모두 있어야 한다. 쓰기는 JSON 문자열 안의 `<` 를 `\u003c`, `>` 를 `\u003e`, `&` 를 `\u0026`, `-` 를 `\u002d` 로 적는다(앞 셋은 Go `encoding/json` 기본, `-` 는 `FormatRecord` 가 바꾼다). 줄바꿈·U+2028·U+2029 도 이스케이프(`\n`·`\u2028`·`\u2029`)라 늘 한 줄이다. 예: 질의 이름 `a-->b` 는 `"query":"a\u002d\u002d\u003eb"` 로 적힌다 — 원문 글자 `-->` 로 적으면 주석이 먼저 닫히고, 읽기도 거부한다.

읽기는 다음 차례로 보고, 앞 단계에서 걸리면 뒤 단계는 보지 않는다.

1. 주석 꼴 — 64 KiB 이하, 한 줄(줄바꿈 없음), 접두·접미 정확 일치(앞뒤 공백 없음), 올바른 UTF-8, 본문에 `--` 없음, 짝 맞는 surrogate 이스케이프, JSON 객체 하나(중복 키·객체 뒤 남은 글자 없음). 어기면 연결 끊김이다 — `v` 가 같은 키로 두 번 나와도 여기서 끊김이다.
2. `v` — 없거나 정수로 읽히지 않으면(문자열 `"1"` 등) 끊김이다. `null` 은 0 으로 읽혀 「모르는 판」이다. 1 이 아닌 정수도 모르는 판이고, 이때 나머지 키는 보지 않는다(`{"v":2}` 만 있어도 모르는 판).
3. 모르는 키 — 하나라도 있으면 모르는 판이다(값이 `null` 이어도).
4. v1 의 나머지 열 키 — 모두 있고 키마다 맞는 타입(`null` 아님), `at` 은 다시 적어도 같은 UTC RFC3339(`…Z`), 아래 표의 길이·범위. 어기면 끊김이다.

| 키 | 뜻 | 꼴 |
| :-- | :-- | :-- |
| `v` | 기록 판 | 정수 `1` |
| `ws` | 작업공간 ID 앞 8자 | 소문자 16진 8자 |
| `dataset` | 자료 이름 | 비지 않은 글(4 KiB 까지) |
| `rev` | 자료 안 판 순번 | 1 이상 |
| `query` | 질의 이름 | 비지 않은 글(4 KiB 까지) |
| `qv` | 질의 판 번호 | 1 이상 |
| `at` | 결과를 보존한 시각 | UTC RFC3339, 초 단위 |
| `result` | 결과 지문 앞 16자 | 소문자 16진 16자 |
| `hash` | 블록 지문 앞 16자 | 소문자 16진 16자 |
| `rows` | 데이터 행 수 | 0~1000 |
| `cols` | 열 수 | 1~30 |

판 이름은 기록에 없고 캡션에만 있다. 주석 한 줄은 64 KiB 까지다. 블록 지문은 표의 정렬·머리 칸·칸 원문을 해시한 것이다 — 열 너비 맞춤 공백과 캡션은 들어가지 않는다(`internal/datareport/hash.go`).

**연결 상태**(`datareport.Classify` — `internal/datareport/classify.go`). 판정 대상은 최상위에서 기록 주석 꼴(앞뒤 공백을 뗀 줄이 접두로 시작)인 HTML 블록, 또는 바로 앞 줄이 그런 주석인 최상위 표·차트다. 목록·인용 안에 든 주석 줄이나 접두가 전혀 다른 줄은 자료 블록으로 보지 않는다(상태 없음 — 보통 HTML 주석). 연결 후보는 주석이 홀로 한 줄인 HTML 블록이고 바로 다음 줄에서 최상위 표나 닫힌 최상위 `:::chart`(안에 표가 있음)가 시작할 때다.

- **연결됨**: 블록 지문이 기록의 `hash` 와 같다.
- **수정됨**: 열 수는 기록의 `cols` 와 같고 블록 지문이 다르다 — 넣은 뒤 칸·머리·정렬·행을 고쳤다.
- **연결 끊김**: 주석이 홀로 한 줄이 아님, 주석을 풀지 못함(위 읽기 1·2·4 단계), 바로 다음이 최상위 표·차트가 아님(다음 줄이 목록·인용·다른 컨테이너인 경우 포함), 닫히지 않은 차트, 차트 안에 표가 없음, 열 수가 `cols` 와 다름. 스냅샷 바꾸기를 열 때는 출처(작업공간·자료·판·질의 판)를 작업공간에서 찾지 못한 것도 끊김이다.
- **모르는 판**: 읽기 2·3 단계에서 걸렸다(`v` 가 `null` 이거나 1 이 아닌 정수, 또는 모르는 키) — 새 판 Itda Hyve 가 쓴 기록일 수 있어 끊김과 가른다.

**다른 뷰어에서는 보통 표다.** GitHub 렌더(`gh api markdown`, gfm, 2026-11-01 — 가짜 값으로 한 번)에서는 기록 주석이 사라지고 표는 보통 표로, `Table: …` 캡션과 `:::chart{…}`·`:::` 줄은 글자 그대로의 문단으로 보였다. Pandoc·Obsidian·VS Code 미리보기는 미확인이다.

## 8. 글·목록·링크·이미지·HTML

- **강조**: `**굵게**`·`*기울임*`·`~~취소선~~`. 한국어 경계를 따른다 — `**"인용"**은`·`**결론:**입니다` 도 굵게 된다(CommonMark CJK-friendly). GitHub 등 다른 뷰어에서는 글자로 보일 수 있다.
- **줄바꿈**: 문단 안 줄바꿈은 공백이 된다. 줄을 바꾸려면 줄 끝에 `\` 또는 공백 둘, 표 칸 안에서는 `<br>`.
- **목록**: `-`·`1.`·작업 목록 `- [ ]`·`- [x]`. 번호는 첫 항목의 숫자부터.
- **목록 기호 사다리**: 개조식(`□ → ○ → - → ·`)·공문(`1. → 가. → 1) → 가) → (1) → (가) → ① → ㉮`) 기호는 **글자로 적지 않는다**. 보통의 `-`·`1.` 목록을 들여 써서 단계를 나누고 frontmatter `list-style: gaejosik`(비순서 목록)·`gongmun`(순서 목록)·`[gaejosik, gongmun]`(둘 다)·`plain`(끔)으로 켠다. `mono` 테마는 둘 다 켜져 있다. 글자로 적으면 `list-marker` 경고가 난다.

```markdown
---
list-style: [gaejosik, gongmun]
---

- 추진 배경
  - 고객 요청 증가
    - 월 20건 → 45건

1. 추진 계획
   1. 1단계: 설계
   2. 2단계: 구축
```

- **링크**: 상대 주소·`#조각`·`http`·`https`·`mailto`·`tel` 만 링크가 된다. 그 밖(`javascript:`·`file:` 등)은 글자만 남고 `unsafe-url` 경고. 주소 글자(`https://…`·`www.…`)는 저절로 링크가 된다(`ftp://…` 글자는 막힌 주소라 `unsafe-url` 경고).
- **이미지**: 상대 경로(문서 폴더 아래 실제 파일만)·`data:image/…`·원격(`http(s)`). 원격 이미지는 기본으로 불러오지 않고 `remote-image` 경고를 낸다 — 메일로 온 문서의 추적 그림을 막는다. 문서 창에서 문서마다 켤 수 있다.
- **raw HTML 은 그리지 않는다.** 속성 없는 `<br>`·`<sub>`·`<sup>`·`<kbd>`·`<mark>`·`<u>`·`<ins>`·`<small>` 과 5장의 쪽 나눔만 예외이고, 짝이 맞아야 남는다. 나머지는 버리고 `raw-html` 경고. HTML 주석은 조용히 버린다.
- **코드 블록**: ```` ```언어 ```` — 알려진 언어는 Go 렌더에서 구문 강조한다(`mdoc/render.go` `codeBlock`). 블록 64KiB·1000줄 또는 문서 강조 합 256KiB를 넘으면 원문 코드로 보인다. 언어를 생략하거나 모르는 언어면 강조하지 않는다(언어를 생략하고 파일명을 적으면 파일명으로 짐작한다 — 아래). ```` ```mermaid ```` 는 그림, ```` ```math ```` 는 수식이다. 2줄 이상 블록은 미리보기(쪽·이어보기·슬라이드·발표·PDF)와 공유 보기의 왼쪽에 줄 번호가 붙는다(#435 — 1줄 블록·mermaid·수식·안전 모드 원문·발표자 노트는 제외). 쪽이 나뉘어 잘려도 번호는 이어지고, 번호를 글자로 복사·검색하는 일은 없다(화면이 그리는 표식). 문서 전체에서 끄려면 frontmatter 에 `code: {line-numbers: false}`(또는 `code: false`)를 넣는다.
- **코드 블록 파일명**: 여는 펜스에 파일명을 적으면 코드 위에 머리 띠로 그린다(#441). 표기는 둘 다 — ```` ```yaml title="docker-compose.yml" ```` (정식, Docusaurus·MkDocs 관습) 과 ```` ```yaml:docker-compose.yml ```` (줄임, Zenn·Qiita 관습). `title='…'`·따옴표 없는 `title=값` 도 받는다. 언어를 비우면 ```` ```title=".env" ````·```` ```:main.go ```` 처럼 파일명 확장자로 강조 언어를 짐작하고, 짐작하지 못하면 일반 코드다. 파일명은 띠로만 그려져 코드 글자(복사·줄 번호·검색)에 끼지 않고, 쪽이 나뉘어 잘린 뒷조각에도 다시 붙는다. mermaid·수식이 그림으로 그려지면 띠 없다(그림 실패로 코드로 남으면 띠가 있다).
- **코드 블록 단 나누기**: 여는 펜스에 `cols=2`·`cols=3` 을 적으면 코드 블록 하나를 2·3단으로 흘려 그린다(#487) — ```` ```python title="app.py" cols=2 ````. 단 높이는 자동으로 고르고(단 위치를 직접 정하는 문법은 없다), 줄 번호는 단을 넘어 이어지며, 한 원문 줄은 접혀도 두 단에 걸쳐 잘리지 않는다. 파일명 띠는 단 위 전체 너비에 한 번이다. 쪽·슬라이드에서 넘쳐 나뉜 조각도 조각마다 같은 단 수로 그리고 번호를 이어 간다. 본문에 바로 놓인 cols 블록은 cols 가 없을 때보다 더 잘리지 않는다(인용문·상자 안 블록은 미검증 — 수천 자짜리 한 줄이면 더 잘릴 수 있다, #491) — 단으로는 빈 쪽(슬라이드)에도 못 넣는 조각(단 너비에서 쪽보다 긴 원문 줄 등)은 그 조각만 단을 풀어 1단으로 cols 없는 블록과 같게 나뉜다(`web/pager.js` `forceFit`). 뒷조각은 다시 단으로 시작한다. cols 없는 블록도 잘리는 경우(1단으로도 쪽보다 긴 원문 줄)는 그 조각이 1단인 채 잘려 보인다. 줄 번호를 frontmatter 로 꺼도 단은 나뉜다(번호만 안 보인다). 줄 강조와 함께 쓸 수 있다 — ```` ```python cols=2 {2,5} ````. 띠는 그 줄이 놓인 단 너비 안에만 깔린다(줄 번호를 꺼도 같다). 1줄 블록·발표자 노트 안 블록은 단을 나누지 않는다. 값은 따옴표 없는 `2`·`3` 만 — `cols=1` 은 단 없음과 같고, 그 밖(`cols=4`·`cols="2"`)은 펜스 줄 번호로 `bad-attribute` 경고를 내고 무시한다. 다른 속성의 따옴표 값 안(`title="a cols=2"`)은 단 지정이 아니다. mermaid·수식이 그림으로 그려지면 해당 없다(그림 실패로 코드로 남으면 적용된다). 긴 코드 하나는 `cols=`, 파일 둘을 나란히 놓을 때는 `::::columns` 로 블록을 나눈다(줄 번호가 각각 1부터).
- **코드 줄 강조**: 여는 펜스에 강조할 줄을 `{…}` 로 적으면 그 줄에 띠를 깐다(#479) — ```` ```go {1,3-5} ````(언어 뒤 공백 있어도 없어도 — ```` ```go{1,3-5} ````), 언어 없이 ```` ``` {2} ````, 파일명과 함께 ```` ```go title="a.go" {2-3} ````·```` ```go:a.go {2} ````. 번호는 쉼표·공백으로 가르고 `a-b` 는 범위다. 파일명 안(`title="…"` 값, `언어:파일명` 의 파일명)에 적힌 `{…}` 는 파일명 글자 그대로다 — 강조는 파일명 뒤에 공백을 두고 적는다(```` ```go:a.go {2} ````). 블록 줄 수 밖 번호는 버리고, 거꾸로 범위(`5-3`)·0 은 경고와 함께 버린다(강조할 수 있는 줄 번호는 1000까지 — 더 긴 블록도 그대로 보이고 번호도 붙는다). Deckset 덱을 가져온 경우처럼 펜스 **바로 앞** 문단에 `[.code-highlight: 1, 3-5]`(또는 `all`·`none`)만 적어도 된다 — 그 문단은 출력에서 빠진다. 지시어를 여러 개 이어 적으면(Deckset 의 단계별 강조) 첫 것만 쓰고 경고하며, 펜스에 `{…}` 도 있으면 `{…}` 가 이긴다. 펜스가 바로 뒤에 없는 지시어는 글자로 보인다. 띠는 미리보기(쪽·이어보기·슬라이드)·발표·PDF·인쇄·공유 보기에 그려지고, 줄 번호를 끈 문서·1줄 블록·발표자 노트에서도 강조된다(번호는 없이). 코드 글자(복사·검색)는 바뀌지 않는다.
- **수식**: `$E = mc^2$`(글 안)·`$$…$$`(블록). `$30 와 $40` 같은 금액은 수식이 아니다. 수식 안의 퍼센트는 `\%` 로 쓴다(`%` 부터 줄 끝은 TeX 주석) — [수식 안내서](math.md).
- **흐름도**: ```` ```mermaid ```` 의 `flowchart`·`graph` — [그림 안내서](diagrams.md).

````markdown
값은 $\frac{a}{b}$ 이다. 금액 $30 와 $40 은 글자다.

$$
\sum_{i=1}^{n} x_i
$$

```mermaid

```
````

### 코드 줄 강조 예

발표·강의에서 「지금 볼 줄」을 짚을 때 쓴다. 여는 펜스 끝에 줄 번호를 `{…}` 로 적는다.

````markdown
```python {2,4-5}
def total(items):
    subtotal = sum(i.price for i in items)   # 2줄 — 강조
    shipping = 3000
    if subtotal >= 50000:                    # 4~5줄 — 강조
        shipping = 0
    return subtotal + shipping
```
````

| 적는 법 | 뜻 |
|---|---|
| ```` ```go {3} ```` | 3줄 하나 |
| ```` ```go {1,3-5} ```` | 1줄과 3~5줄(쉼표·공백으로 가르고 `a-b` 는 범위) |
| ```` ```go{1,3-5} ```` | 언어에 붙여 써도 같다 |
| ```` ``` {2} ```` | 언어 없는 코드 |
| ```` ```go title="main.go" {2-3} ```` · ```` ```go:main.go {2} ```` | 파일명 띠와 함께 — 파일명 **뒤에 공백**을 두고 적는다 |

Deckset 에서 가져온 덱은 고치지 않아도 된다 — 펜스 바로 앞 줄의 지시어를 그대로 읽는다.

````markdown
[.code-highlight: 2, 4-5]
```python
…
```
````

`[.code-highlight: all]`(모든 줄)·`[.code-highlight: none]`(강조 없음)도 받는다. 지시어 줄은 화면에 나오지 않는다. 지시어를 여러 개 이어 적은 Deckset 의 단계별 강조(넘길 때마다 강조가 바뀜)는 아직 없어 첫 지시어만 쓰고 경고한다(10장).

강조 띠는 미리보기·슬라이드·발표·PDF·인쇄·공유 보기에 똑같이 그려지고, 줄 번호를 끈 문서(`code: {line-numbers: false}`)에서도 그려진다. 띠 색은 테마 토큰 `--code-hl-bg`·`--code-hl-bar` 로 바꾼다(GUIDE-document-themes). 코드를 복사하면 원문 그대로다.

### 한국어 업무 문서의 함정

표준대로 읽으면 흔한 표기가 다른 뜻이 되는 곳이다. 렌더는 다른 뷰어와 같게 두고 경고만 낸다.

| 코드 | 이렇게 쓰면 | 이렇게 된다 | 고치는 표기 |
|---|---|---|---|
| `tilde-range` | `3~5명, 10~20명` | `~5명, 10~` 이 취소선 | `3\~5명` |
| `date-list` | 줄 머리 `2026. 10. 14.` | 번호 목록 안 번호 목록 | `2026\. 10. 14.` |
| `list-marker` | `- ○ 내용`·`1. 가. 내용` | 기호가 글자로 겹침 | 기호를 빼고 `list-style`(위) |

틀린 예 — `~5명, 10~` 이 취소선이 되고 `tilde-range` 경고가 난다:

<!-- md-example warn="tilde-range" -->
```markdown
참석 3~5명, 예산 10~20만 원
```

고친 예:

```markdown
참석 3\~5명, 예산 10\~20만 원

2026\. 10. 14.(수) 교통정책과
```

## 9. 경고 코드

경고는 원문 줄 번호와 함께 문서 창의 경고 단추에 모인다(`md_check`·`itda-hyve md --check` 도 같은 목록). 경고가 나도 문서는 그려진다 — 버리거나 글자로 둔 곳을 알린다.

<!-- warn-codes:begin -->
| 코드 | 뜻 | 고치는 법 |
|---|---|---|
| `raw-html` | 그리지 않은 HTML | 마크다운으로 바꾼다(8장 예외 태그 말고는 그려지지 않는다) |
| `frontmatter-invalid` | YAML 이 깨져 frontmatter 를 본문으로 그림 | 콜론 뒤 공백, 따옴표 짝, 들여쓰기를 고친다 |
| `frontmatter-value` | 아는 키의 값 꼴이 틀려 무시함 | 2장 표의 값 꼴로 |
| `unsafe-url` | 막은 링크·이미지 주소 | `http(s)`·`mailto`·`tel`·상대 주소로 |
| `remote-image` | 불러오지 않은 원격 이미지 | 그림 파일을 문서 폴더에 두고 상대 경로로(또는 문서 창에서 원격 그림 켜기) |
| `bad-attribute` | 알아보지 못한 `{…}` 속성 | `{#id .class key=value}` 꼴로, 길이는 6장의 꼴로 |
| `unclosed-container` | 문서 끝에서 닫힌 `:::` | 닫는 `:::` 줄을 넣는다 |
| `indented-close` | 4칸 이상 들여쓴 `:::` 가 닫는 줄로 읽히지 않아 그 컨테이너가 감싼 블록 끝까지 이어짐(뒤 제목 수를 함께 알림) | 닫으려던 줄이라면 들여쓰기를 여는 `:::` 와 같은 칸으로 줄이고 앞에 빈 줄을 둔다 — 문서 창 경고 목록의 「고치기」 |
| `duplicate-id` | 직접 적은 id 가 겹침 | id 를 하나씩 다르게 |
| `too-complex` | 강조·링크 표시가 너무 많거나 블록 중첩이 64겹을 넘어 글자로 둠 | 문단을 나누고 중첩을 줄인다 |
| `chart` | 차트를 그리지 못했거나 일부 값을 버림 | 메시지대로 — [차트 안내서](charts.md) 10장 |
| `math` | 그리지 않은 수식(원문 그대로), 또는 TeX 주석(`%`)이 지운 글 | 메시지의 명령·문법을 고친다. 퍼센트는 `\%` — [수식 안내서](math.md) |
| `diagram` | 그리지 않은 mermaid 그림, 또는 무시한 줄(`style`·`click` …) | [그림 안내서](diagrams.md) 3장 |
| `tilde-range` | 범위로 보이는 `~` 가 취소선이 됨 | `\~` |
| `date-list` | 줄 머리 날짜가 번호 목록이 됨 | `2026\.` |
| `list-marker` | 목록 항목에 기호·항목 번호를 글자로 적음 | 기호를 빼고 `list-style` |
| `folder-slides-unused` | 폴더 `_metadata.yml` 에 `slides:` 설정이 있는데 문서에 `slides:` 가 없어 슬라이드로 열지 않음(`slides:` 를 둔 가장 가까운 폴더 파일의 경로를 알림) | 안내다 — 문서마다 일괄로 고치지 말고 의도를 확인한다. 슬라이드로 쓸 문서라면 frontmatter 에 `slides: true`(폴더에 `slides:` 맵이 있으면 그 하위 설정이 채워진다), 쪽 문서로 둘 거면 `slides: false` 로 정하면 경고가 사라진다 |
| `unknown-theme` | 모르는(또는 쓸 수 없는) 테마 — `classic` 등으로 보임 | 3장의 이름으로 |
<!-- warn-codes:end -->

틀린 예 — 이렇게 쓰지 않는다. 글자만 남고 `raw-html`·`unsafe-url` 경고가 난다:

```markdown
<span style="color:red">빨간 글</span>

[열기](javascript:alert(1))
```

## 10. 지원하지 않는 것

넣지 않았거나 아직 없는 것이다. 쓰면 글자로 보이거나(경고 없이) 경고가 난다.

- `==강조==`·`++삽입++`·이모지 단축어(`:smile:`)·위키 링크(`[[문서]]`)·변수 치환(`{{…}}`)
- 파일 포함 — CSV 도 문서가 가리키지 않는다. 편집기의 **CSV 표** 넣기 도구가 표로 가져온다
- 색·글꼴·크기 지정(`style`·`<font>`) — 테마가 정한다
- 표 칸 병합, 쪽 아래 각주, 식 번호(`\tag`·`\label`)
- 인라인 디렉티브 `:이름[…]`·한 줄 `::이름`
- mermaid 의 흐름도 말고 다른 그림 종류(시퀀스·간트 등)
- 코드 줄 단계별 강조(Deckset 의 `[.code-highlight:]` 여러 개·Slidev 의 `{2|3-4|all}` — 발표에서 넘길 때마다 강조가 바뀜). 첫 단계만 보인다. 원문 주석 표식(`// highlight-next-line`)·MkDocs `hl_lines="…"` 도 받지 않는다
